# chinese_tn 全面测试与不足清单（面向 TTS 前端薄层用途）

日期：2026-09-07
状态：已修复——P0-P3 全部落地（类别表架构重构 + 18 类实现），回归全绿（ITN 328/328、TN 120/120）

## 用途定位（本文档的前提）

`chinese_tn` 将作为 supertonic-mini TTS 前端的**薄层 TN**：

- 底层先过 misaki 的 `zh_normalization`（PaddleSpeech 血统，`misaki.zh_normalization.text_normalization.TextNormalizer`）；
- `chinese_tn` 只补 misaki 处理不了 / 处理不好的部分；
- 集成时**先做中英切段、只对中文段跑 TN**——英文句里的数字（`iPhone 15`、`GPT-4`）不属于 chinese_tn 的责任范围，本文不据此扣分。

**关键架构结论（先说）**：实测发现 misaki 的数值读法是 ASR 风格（`100→幺零零`、`110→幺幺零`、`99999→九九九九九`），不适合直接喂 TTS；而 chinese_tn 的数值读法（`一百`、`一百一十`、`九万九千九百九十九`）才是 TTS 要的。所以**实际分工应反过来：chinese_tn 为主、misaki 为辅**——chinese_tn 先吃掉自己能转的数字，转不干净的（带未支持符号的）留给 misaki。这带来本测试最重要的发现：**chinese_tn 的 number 正则会"抢走"紧邻未支持符号的数字**（`25℃→二十五℃`、`$5→$五`），数字一旦变成中文，下游 misaki 就再也处理不了了（misaki 只认 ASCII 数字）。修复"抢数字"问题是薄层方案成立的前提。

## 不足分类汇总

**a) 完全没覆盖的模式**
1. 货币符号 $ ￥ € £（→ 美元/元/欧元/英镑，前缀重排）
2. 公制单位 km cm mm kg g ml L m 及 km/h（含大小写混合 ML/Kg）
3. 度符号 ℃ °C °F（→ 摄氏度/度/华氏度，负号→零下）
4. 范围表达式：连字符 `-`、波浪号 `~／～`（misaki 会，chinese_tn 抢数字导致没用上）
5. ISO 日期 `2008-08-08`、斜杠日期 `2026/09/07`
6. 千分位逗号 `1,234,567`
7. 号码上下文词表（尾号/订单号/车牌/拨打），短号 110/911/12306
8. 科学计数法 `1e5`（低优先级）

**b) 读法不符合 TTS 口语习惯**
1. `9:00→九点零零分`（应"九点整"或省略）
2. 多段比值 `2:3:4` 只转前两段，尾段数字漏转成 ASCII
3. 电话逐位用"一"不用"幺"（TTS 惯例号码读幺，可做开关）

**c) 与 misaki 重叠（薄层定位下的取舍）**
- 重叠且 chinese_tn 更优：整数/小数/百分/分数/日期/时间/序数——misaki 是 ASR 风格（幺、删尾零、100→幺零零），**这些应以 chinese_tn 为主，misaki 兜底**
- 重叠且 misaki 更优：范围（3-5、3~5）、ISO/斜杠日期、℃/°C、km/cm/kg/ml/m、连字符电话——**chinese_tn 若不打算自做，必须放行别抢数字**（见 d-1）

**d) 边界 bug（正则误匹配/漏匹配）**
1. **抢数字**：number 组无条件吃掉紧邻 `℃ $ ￥ km` 等符号的数字，输出残句并阻断下游 misaki——薄层架构下最致命
2. **负号误伤**：`-` 一律当前置负号 → `3-5→三负五`、`2008-08-08` 灾难、`010-12345678` 读成负数、`A-320`
3. **斜杠日期被分数规则砸碎**：`2026/09/07→九分之二千零二十六/零七`
4. `12:30:45:60` 尾段漏转（`:60` 残留）
5. ≥11 位一律逐位，`123456789012`（千億级）应按数值读

## 补充实现建议（按优先级）

1. **P0 放行未支持符号**：`number` 组加负向断言，数字后紧跟 `℃°$￥€£kmcgmlLKMG/%` 等未处理符号时整体不匹配（留给 misaki）。这是薄层方案成立的前提，一行正则的事。
2. **P0 负号/连字符消歧**：`-` 仅在「前无数字、后随数字」且非 `年`/日期/范围语境时当负号；`A-B` 两侧都是数字 → 范围（`三到五`）或放行；ISO 日期 `YYYY-MM-DD` 整体识别。
3. **P1 温度**：`-?数+℃/°C→（零下）N度`、`℉/°F→华氏度`；负温度统一"零下"（口语）而非"负"。
4. **P1 货币**：`$N→N美元`、`￥N→N元`、`€N→N欧元`、`£N→N英镑`（前缀重排）。
5. **P1 斜杠日期** `YYYY/MM/DD`（并把 fraction 组限定为分母分子均 ≤3 位数或非日期形态）。
6. **P2 公制单位**（若决定自做而非留给 misaki）：km/cm/mm/kg/g/ml/L/m 大小写不敏感 + km/h→千米每小时；注意 misaki 在 `10mm→米米`、`500g→逐位`、`2L`、大小写混合上也有 bug，自做更可控。
7. **P2 号码上下文词表**：`尾号|订单号|车牌|拨打|客服|QQ号` 等前后词触发逐位 + 可选"幺"读法；车牌正则 `[京沪粤鄂皖川渝][A-Z]·?\d{5}` 逐位。
8. **P2 千分位逗号**：`\d{1,3}(,\d{3})+` 合并后按数值读。
9. **P3 整点时间**：`HH:00→H点整`（或至少省"零零分"）。
10. **P3 杂项**：多段比值 `a:b:c`、时间四段尾巴漏转、11~13 位纯数值按数值读、科学计数法。

### d) chinese_tn vs wetext 读法口味差异

- `98年`：chinese_tn `九八年`（口语）vs wetext `九十八年`——TTS 场景 chinese_tn 更自然。
- `5km`：`五千米` vs `五公里`——都自然，wetext 更口语，chinese_tn 更书面，无对错。
- `3km/h`：`三千米每小时` vs `每小时三公里`——语序都通。
- `25℃`：`二十五度` vs `二十五摄氏度`——chinese_tn 偏口语（省"摄氏"），可接受。
- `2L`：`二升` vs `两升`——wetext 的"两"更地道；chinese_tn 全局用"二"（含 `2L→二升`、量词前不改"两"），是已知取舍。
