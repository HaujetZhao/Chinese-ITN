# chinese_tn 设计文档

日期：2026-09-07
状态：已与用户对齐，待实现

## 目标

为本库新增中文文本正则化（TN, Text Normalization）能力：将文本中的阿拉伯数字转换为中文读法，方向与现有 ITN（`chinese_itn.chinese_to_num`）相反。典型用途：TTS 前端。

```python
from chinese_tn import num_to_chinese

num_to_chinese('明天有62%的概率降雨')   # 明天有百分之六十二的概率降雨
num_to_chinese('13812345678')           # 一三八一二三四五六七八
```

## 范围

首期覆盖三类：

1. **基础数值**：整数、小数、负数、万/亿后缀（`123→一百二十三`、`3.14→三点一四`、`-5→负五`、`20.1万→二十点一万`）
2. **百分比/分数/比值**：`50%→百分之五十`、`2/3→三分之二`、`1:3→一比三`
3. **日期时间**：`2025年10月3日→二零二五年十月三日`、`12:30→十二点三十分`

不做：号码类上下文词表（号码/电话/单号邻近词识别）、范围表达式（`15-20`）、单位换算、口语读法（幺/两）。需要时后续追加。

## 方案选型

采用**镜像独立包**：同仓库新建 `chinese_tn/` 包，与 `chinese_itn/` 平级、零代码耦合。两边方向相反（ITN 是中文数字词法分析，TN 是 ASCII 数字解析），无可共享逻辑，强行统一只会造出抽象层。

落选方案：
- 单文件 `chinese_tn.py`：数值分级转换的内在复杂度与分发逻辑混在一起，可读性差
- 双向统一 normalizer：为「可互逆」这个无人要求的目标付架构代价，过度设计

## 包结构

```
chinese_tn/
  __init__.py    # 导出 num_to_chinese
  numbers.py     # 核心数值→中文：整数分级转换、小数、逐位读
  replacer.py    # 扫描正则 + 类别分发 + num_to_chinese() 入口
test_cases_tn.txt          # TN 用例，格式同现有 `输入 -> 期望输出`（已被 .gitignore 的 test_cases_*.txt 覆盖）
run_test.py                # 重构：抽 run_suite()，依次跑 ITN / TN 两套
CLAUDE.md / readme.md      # 补充 chinese_tn 的结构与用法
```

对外只一个函数，与 `chinese_to_num` 完全对称：文本进、文本出；正则不命中的片段原样通过；无异常路径。

## 扫描与分发顺序

一段总扫描正则抓出候选片段，按优先级判定（先具体后一般，与 ITN 管线哲学一致）：

1. **日期** `\d{2,4}年\d{1,2}月(\d{1,2}[日号])?` —— 年月日可部分出现（`10月3日`、`86年`）
2. **时间** `\d{1,2}:\d{2}(:\d{2})?` —— 校验 h≤23、m/s≤59，不满足则落入比值
3. **百分/千分** `-?\d+(\.\d+)?[‰%]`
4. **分数** `\d+/\d+`
5. **比值** `\d+:\d+`（时间没接住的全部到这里）
6. **数值** `-?\d+(\.\d+)?` 后可跟 `万|亿` —— 末位判定：以 0 开头或长度 ≥ 11 的纯整数串 → 逐位读（11 位为手机号长度，8~10 位串按数值读）；否则按数值读

## 转换规则

**整数**（`numbers.int_to_chinese`，核心）：按 4 位一级分节（个/万/亿），节内千百十转换；处理零的合并（节内多个零合并为一个）与节间补零。标准书面风格，全部用「二」不用「两」。典型结果：

| 输入 | 输出 |
|------|------|
| 0 | 零 |
| 10 | 十 |
| 110 | 一百一十 |
| 105 | 一百零五 |
| 1005 | 一千零五 |
| 100070000 | 一亿零七万 |
| -5 | 负五 |

**小数**：整数部分按数值、`点`、小数部分逐位；尾随零保留（`1.10→一点一零`），整数部分为 0 时读出（`0.5→零点五`）。

**逐位串**：每位映射 `0→零 … 9→九`（`13812345678→一三八一二三四五六七八`）。

**百分/千分**：`50%→百分之五十`、`32.68%→百分之三十二点六八`、`5‰→千分之五`。

**分数/比值**：`2/3→三分之二`（分子分母倒序）、`1:3→一比三`。

**日期**：年逐位读（`2025年→二零二五年`），月/日按数值读，`日/号` 字原样保留。

**时间**：时按数值；分/秒按数值，小于 10 补「零」（`09:05→九点零五分`）；`13:10:36→十三点十分三十六秒`。

**万/亿后缀**：只转前面的数，单位原样保留（`20.1万→二十点一万`）。

**已知不对称（接受，不解决）**：单独出现的 `2025` 读成「二千零二十五」而非年份读法——日期必须带「年」字才走日期分支，这是判定规则的直接推论。
